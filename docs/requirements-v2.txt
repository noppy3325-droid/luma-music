# Android音楽プレイヤー開発指示書 v2.0

## 1. プロジェクト概要

Apple MusicのiOS 26以降のUI/UXとLiquid Glassデザインを参考にした、Android専用の高品質なローカル音楽プレイヤーを開発してください。

開発対象の主な端末は **Xiaomi 14T** です。

アプリの目標は、Apple Musicに近い洗練されたデザインと、Androidならではの柔軟なローカルファイル管理、高音質再生を両立することです。

有料サブスクリプション、アカウント登録、インターネット接続は不要です。

Appleの商標や著作物をコピーすることなく、独自のアプリとして設計してください。

### 最優先事項

1. Apple Musicに近い美しいUI・UX
2. Liquid Glassの透明感と自然なアニメーション
3. 高度に安定したローカル音楽再生
4. Xiaomi HyperIslandとの連携
5. 横置きのスタンバイモード
6. フォルダー単位のライブラリ管理
7. USB-C DACを使った高音質・ダイレクト再生

見た目だけのプロトタイプではなく、実際に日常使用できる完成版APKを目指してください。

USB DAC関連は、通常再生エンジンから分離できる構成としてください。

## 3. Liquid Glassデザイン

### デザイン方針

Apple Musicの画面構成、視覚階層、操作感を強く参考にしてください。

- 大きなアルバムアート
- 曲情報と操作パネルを整理したレイアウト
- 浮遊するミニプレイヤー
- 半透明のボトムナビゲーション
- アルバムアートから抽出した背景グラデーション
- 透明感・ブラー・光の反射を持つ操作ボタン
- 滑らかなSpring Animation
- 自然な画面間トランジション

Liquid Glassを単なる白い半透明パネルとして実装しないでください。

透過、背後のぼかし、エッジハイライト、光の反射、押下時の変形などを組み合わせ、視覚的な奥行きがあるUIを構築してください。

背後のコンテンツを実際にぼかす必要がある部分では、Androidの描画構造を考慮した実装を採用してください。

パフォーマンスと可読性を損なう過剰なガラス効果は避けてください。

60fpsを基本目標とし、描画負荷が高い環境では品質を自動調整できるようにしてください。

## 5. Xiaomi HyperIsland連携

**重要な必須機能です。**

Xiaomi HyperOS 3以降のHyperIslandへの対応を目指します。

### 必要な機能

音楽再生中、対応するXiaomi端末でHyperIslandから楽曲状態を確認・操作できるようにしてください。

- 再生中の楽曲情報
- アルバムアート
- 再生・一時停止
- 前の曲・次の曲
- タップによるアプリ復帰
- システム側が提供する展開表示

対応する操作は、Xiaomi公式のメディア通知仕様に従って実装してください。

### 実装方針

まずMedia3のMediaSessionとAndroid標準MediaStyle通知を正しく実装してください。

以下を適切に連携します。

- MediaSession
- PlaybackState
- MediaMetadata
- システムメディア通知
- メディア操作用Command
- Androidロック画面の再生操作

Xiaomi公式の「HyperOS 媒体通知適配説明」と「小米超級島 開発指南」を調査し、現行仕様に従ってください。

標準のメディア通知で対応できる場合は、不要なXiaomi専用通知を重複生成しないでください。

Xiaomi独自の拡張が必要な場合は、OSバージョンと機能提供状況を確認したうえで実装してください。

### 互換性

- 対応するHyperOSではHyperIslandを活用
- 非対応のHyperOSでは通常のメディア通知
- その他のAndroid端末でも通常のメディア通知を表示

端末や地域、OSバージョンによって利用できない機能については、対応しているかのように偽装しないでください。

### 検証

Xiaomi 14Tの実機で以下を確認してください。

- バックグラウンド再生
- 画面ロック時
- 他アプリ使用中
- 再生停止・再開
- 楽曲変更
- HyperIslandからの操作

OSが実際にHyperIslandを提供している場合は、島からの操作を検証してください。

## 6. スタンバイモード

**AppleのStandByモードを参考にした、専用の横置き音楽プレイヤー画面を実装してください。**

### 起動条件

標準動作は以下とします。

1. ユーザーがアプリ内の「スタンバイモード」ボタンを押す
2. スタンバイ待機状態になる
3. アプリを前面に表示したまま端末を横向きにする
4. 専用の横画面プレイヤーを表示する

誤作動を避けるため、専用ボタンを押さない限り通常の画面回転だけでスタンバイモードに入らない仕様にしてください。

画面の自動回転設定がオフでも、スタンバイモード中は必要に応じて端末の姿勢センサーを利用し、横向き表示を実現してください。

モード終了後はアプリの通常の画面向き設定に戻してください。

### 横画面レイアウト

左右2カラム構成とします。

**左側：約50%**

- 大きな正方形ジャケット
- アルバムアートの影
- 背景との自然な一体感
- ジャケットの表示・非表示アニメーション

**右側：約50%**

- 楽曲名
- アーティスト名
- 再生位置
- シークバー
- 前の曲
- 再生・一時停止
- 次の曲
- シャッフル
- リピート
- 音量調整

ジャケットとコントロールの距離、文字サイズ、余白を最適化してください。

画面サイズや縦横比が異なる端末でも破綻しないよう、WindowSizeClassなどを参考にレスポンシブに構築してください。

### 背景

アルバムアートの代表色を抽出し、画面全体を覆う滑らかなグラデーションを生成してください。

背景は強めのブラーを適用し、ジャケットと操作パネルを視覚的に際立たせてください。

楽曲変更時には自然なクロスフェードを使用してください。

### スタンバイモード設定

- 画面を点灯したままにする
- 一定時間後に画面を暗くする
- 暗所向け表示
- 画面の明るさ調整
- 時計表示のオン・オフ
- 歌詞表示のオン・オフ
- 焼き付き軽減のための低輝度表示・微小な位置調整

画面常時点灯はユーザーが選択した場合のみ有効にしてください。

アプリが前面にある場合だけ画面点灯状態を制御し、バックグラウンドで端末のスリープを妨害しないでください。

有機EL画面での長時間使用を考慮し、固定要素の焼き付き対策を用意してください。

### 終了条件

以下の操作に対応します。

- 縦向きに戻す
- 戻る操作
- 画面上の終了ボタン

縦向きに戻したときは、直前に表示していた通常のプレイヤーへ滑らかに復帰してください。

音楽再生を中断してはいけません。

## 7. フォルダー単位の楽曲管理

**端末内の全音楽を無条件に取り込む方式にはしないでください。**

ユーザーが指定したフォルダーを読み込む方式を基本とします。

### 初期設定

初回起動時に音楽フォルダーを指定できる画面を表示してください。

AndroidのStorage Access Frameworkを使用し、ユーザーがフォルダーを選択できるようにします。

### 必須機能

- 複数フォルダーの登録
- サブフォルダーの再帰検索
- フォルダーごとの楽曲一覧
- フォルダーの追加・解除
- 手動再スキャン
- 前回登録したフォルダーの保持
- 楽曲追加・削除・変更の検出
- ファイル移動・アクセス権限消失時の適切な処理

`ACTION_OPEN_DOCUMENT_TREE` と永続URI権限を活用してください。

許可がない場所へアクセスしないでください。

元ファイルの移動、コピー、削除は原則として行わず、データベースにメタデータと参照情報を保持してください。

### 対応フォーマット

- MP3
- AAC / M4A
- FLAC
- WAV
- OGG
- Opus

端末・OS・デコーダーによる対応差を適切に処理してください。

### メタデータ

タグから以下を取得してください。

- タイトル
- アーティスト
- アルバム
- アルバムアーティスト
- 年
- ジャンル
- トラック番号
- ディスク番号
- ジャケット
- 歌詞
- サンプルレート
- ビット深度（取得可能な場合）
- コーデック

ファイルのタグが不完全でも安全に動作させてください。

## 8. USB-C DAC再生

**音質を重視した重要機能です。**

USB-C接続の外付けDACを使用した再生に対応してください。

### 基本機能

- USB DACの接続・切断検知
- USB DACへの音声出力
- DACの名称表示
- 取得可能な音声仕様の表示
- サンプルレートの確認
- 出力経路の表示
- DAC切断時の安全な処理

### 再生モード

以下の3種類を設計してください。

#### A. 通常再生

Media3 / ExoPlayerによる標準再生。

Androidのオーディオシステムを利用します。

Bluetooth、内蔵スピーカー、一般的なUSB DACなどで安定して動作することを優先してください。

#### B. 高音質USB再生

USB DACの接続時に、AndroidのAudioManagerが提供する機能を利用して適切な出力設定を選択してください。

Android 14以降の対応端末では、以下を利用可能か確認してください。

- AudioManager.getSupportedMixerAttributes()
- AudioManager.setPreferredMixerAttributes()
- AudioMixerAttributes
- 出力デバイスの検出
- 対応サンプルレート・ビット深度の確認

楽曲の形式とDACの対応状況を踏まえ、不要なリサンプリングや音声加工を可能な範囲で回避してください。

#### C. ビットパーフェクト再生

対応環境で、元の音声データを不要に改変せず出力するモードです。

以下の条件を重視します。

- 不要なリサンプリングをしない
- 不要なビット深度変換をしない
- ソフトウェア音量変更を適用しない
- EQ・音声エフェクトを適用しない
- 不要なオーディオミキシングを避ける

Android 14以降の `MIXER_BEHAVIOR_BIT_PERFECT` が利用できる場合は、その適用を検討してください。

ただし、このAPIは全端末で利用できるわけではありません。

Media3の標準再生のみでビットパーフェクトが実現できると仮定しないでください。

必要であれば、AudioTrackベースの専用PCM出力エンジンを設計してください。

### 再生エンジンの分離

`AudioOutputEngine` のような抽象インターフェースを設計し、以下の実装を交換可能にしてください。

- StandardMedia3Engine
- UsbHighQualityEngine
- UsbBitPerfectEngine

MediaSessionServiceを中心に再生状態を統一し、エンジンを変更してもUI、再生キュー、通知、HyperIsland連携が破綻しないようにしてください。

低レベル再生エンジンが必要になった場合は、再生位置、曲変更、音声フォーカス、通知、バックグラウンド再生との連携を十分に設計してください。

### USBの直接制御について

Androidのオーディオフレームワークを迂回してUSB Host APIからDACを直接制御する方法は、標準APIでは十分に実現できない場合の追加候補とします。

この方式を採用する場合は、USB Audio Class対応、デバイス権限、アイソクロナス転送、Androidの制限、通知音やアラームへの影響まで調査してください。

安易に独自USBドライバーを実装しないでください。

### 表示する音声品質情報

再生画面から次の情報を確認できるようにしてください。

- ファイル形式
- ソースのサンプルレート
- ソースのビット深度
- 実際の出力デバイス
- 確認可能な出力サンプルレート
- 使用中の再生モード

`Bit-perfect` の表示は、対応が確認され、必要な条件を満たした場合だけにしてください。

出力状態を検証できない場合は「未確認」と表示してください。

例：

- USB DAC接続中
- FLAC / 24bit / 96kHz
- 出力：USB Audio
- モード：高音質USB再生
- ビットパーフェクト：未確認

実際の出力サンプルレートが取得できない場合、元ファイルのサンプルレートを出力値と偽って表示しないでください。

### 安全性

ビットパーフェクト再生ではソフトウェア音量制御が効かない可能性があります。

切り替え時には警告を表示し、DAC側の音量調整を確認してください。

DACが切断された際に突然スマートフォンのスピーカーから大音量で鳴らないよう、安全な停止・出力切り替え処理を実装してください。

## 9. バックグラウンド再生

MediaSessionServiceを使用してください。

以下を必須とします。

- アプリを閉じても音楽を再生
- Androidのメディア通知
- ロック画面操作
- Bluetoothイヤホン操作
- 有線イヤホン操作
- オーディオフォーカス制御
- イヤホン切断時の一時停止
- 再生キューの維持
- 再生位置の保存

Xiaomi HyperOSの電池最適化やバックグラウンド制限で再生が妨げられる場合は、ユーザーに適切な設定手順を案内してください。

過剰なバックグラウンド権限を無断で要求しないでください。

## 11. アーキテクチャ

以下の責務を分離してください。

- UI / Design System
- Navigation
- Library Repository
- Metadata Scanner
- Folder Access Manager
- Playback Controller
- Audio Output Engine
- MediaSession Service
- HyperOS Integration
- Standby Mode Controller
- Lyrics Repository
- Settings Repository

Compose UIは再生エンジンの内部状態を直接操作しないでください。

再生情報はStateFlowなどを通じて統一的に配信してください。

音楽の再生状態はSingle Source of Truthで管理します。

画面回転やActivityの再生成で再生状態が消失しないようにしてください。

- 指定したフォルダーの楽曲だけを登録できる
- 曲を連続再生できる
- 再生中にアプリを閉じても停止しない
- プレイリストが保持される
- 歌詞が正しく表示される
- Bluetoothイヤホンから操作できる
- Liquid Glassデザインが主要画面で機能する
- スタンバイモードを有効化し、横向きで専用UIが表示される
- スタンバイモード中も正常に再生操作できる
- 標準メディア通知が機能する
- 対応HyperOS環境ではHyperIsland連携を確認する
- USB DACへの通常再生ができる
- 高音質・ビットパーフェクト再生は実際に対応を検証する
- 非対応DACやOSでも通常再生にフォールバックする

ハードウェアやOSへの依存がある機能は、実装済み・検証済み・未検証・非対応を分けて報告してください。

## 14. 開発エージェントへの指示

- 計画書やUIモックアップのみで終了しないこと
- 各フェーズで実際に動作するコードを作成すること
- 実機が利用できない場合はエミュレーターや自動テストで検証し、実機で未検証の項目を明記すること
- 未実装機能を動作するように見せかけないこと
- デザインと再生性能を同等に重視すること
- 依存ライブラリの互換性とライセンスを確認すること
- エラーを隠さず修正すること
- 最終的にソースコードとビルド可能なプロジェクトを完成させること

**このアプリは、日常的に長時間使う音楽プレイヤーです。美しいUIと、確実な音楽再生、音声出力の信頼性を最優先してください。**
